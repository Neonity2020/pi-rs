# 08 面板与管理面

> 来源：官方 `docs/005-panel.md` 与 `docs/006-deployment.md`（Management API 一节），对照 `src/app/http.ts`、`src/app/api.ts`、`src/app/views/*`、`src/client/*`。
> 面板是哲学的又一推论：**监督界面的唯一使命是回答"现在有什么需要我"**。

## 1. 打开面板要回答的三个问题（按优先级）

1. **现在有什么需要我吗？**（Overview 第一屏：等待人的票 + 系统问题）
2. **系统健康吗、做的事对吗？**（各页健康与统计）
3. **某件工作的历史是什么——从 Trigger 到 Eval 到 Ticket？**（详情页时间线）

健康状态不占空间；每个数字都能点开等于该数字的列表（**数量与列表长度恒等**，不许矛盾）。

## 2. 页签

页签按工作流排列：**Overview → Source → Trigger → Eval → Execution → Settings**。仓库/账号 setup 未成功前，Overview 只显示缺什么并链接到对应设置。

| 页签 | 内容 |
| --- | --- |
| Overview | 等待人的票、系统问题、最近 24h 活动计数、Executor 负载；每块链接到详情页 |
| Source | Source 状态、setup 问题、非零计数；被过滤 Trigger 与被丢弃消息同样取 24h 窗口 |
| Trigger | Thread 列表（按订阅中/评估中/24h 新触发/全部过滤）；Thread 显示 Trigger（新在前）、Decisions、订阅 |
| Eval | Decisions 及其原因与命中规则 |
| Execution | Executor 状态、暂停处理开关、票列表（Open/Pending/Working/Waiting for a Trigger/Ended）；票详情=操作、授权、待发输入、订阅、Assignments |
| Settings | Sources / Eval / Execution / Prompts / Deployment 五组；每组带保存历史 |

**记录细节**：被丢弃消息链接到其票（无票则到 Thread）；Source 页解释会话消失或停听的原因；执行器仍持有的人类跟帖标"Delivered to Ticket"（无 Eval）；"Evaluate again" 可把被过滤/unavailable/无有效判定的 Trigger 送回 Eval；票详情可 Retry（delivery/blocked/failed 阶段）；已结束票显示结果（"Pull request merged"、"Stopped by a person"）。

## 3. 设计原则（官方七条）

1. **聚焦要紧的事**：每个元素必须回答三问之一，否则删除；数字只在改变监督者行为时才出现；
2. **精确的定义**：分类可检验、互斥且完备（票 stage 表即典范）；标签说"等谁、需要什么"，不说内部状态码；
3. **一个概念一处**：Source 状态在 Source；Thread/Trigger 在 Trigger；Decision 在 Eval；票在 Execution；Overview 只汇总并链接；
4. **领域结构**：用领域术语；内部标识符只出现在折叠细节里，能解析出名字就用名字；
5. **诚实状态**：计数 = 所链接列表的长度；任何状态不得与另一事实矛盾；
6. **默认安静**：健康状态不占额外空间；问题必须可行动（一次性网络错误不够格）；等待人的行直接内嵌操作按钮；解释每页一句，更多放 (?) 提示；破坏性操作需确认；
7. **控件一致**：使用 DSH 设计令牌；同一信息处处同样呈现；每个设置块只有一条保存栏，仅在"有改动/保存中/保存失败"时可见。

## 4. 管理 API（`/orchestrator/api`）

面板本地 HTTP API，agent 也可调用（`SETUP.md` 的配置保存、服务脚本的 `GET state` 都靠它）。

**访问控制**：仅回环地址；必须带 `x-orchestrator-request: 1` 头；Host 必须 `127.0.0.1:<port>` 或 `localhost:<port>`；缺头或跨站 Origin ⇒ 403。**API 保存拥有面板级权限**——可改执行环境与 setup 账号字段（主会话工具保存不可以）。

| 请求 | 返回 |
| --- | --- |
| `GET state` | setup（问题与已解析账号）、health（每部件条目）、load（运行中会话/排队票/maxWorkers）、paused、masterId |
| `GET settings` | policy/eval/executor 块（值+修订号）、Source 实例（值+表单+问题）、policyVersion、执行环境 |
| `GET sources` | 每个 Source：状态（missing/off/error/setup/starting/paused/ready）、健康、24h 统计、被过滤 Trigger、被丢弃消息（最新在前，含原因 channelGone/channelIgnored） |
| `PUT settings/<block>` | 保存整块值（乐观并发：带修订号，409=过期）；返回 policy_changed / restarting |
| `POST executor/pause` | 暂停/恢复处理 |
| `POST setup/check` | 重跑 setup（= 重启进程）；无可修则拒绝 |
| `POST policy-sync/<id>` | 立即同步允许名单（返回名单与增删） |
| `GET prompts` / `PUT prompts` | 读/存提示词配置（current/defaults/sections/skillName/skillPrefix/builtin） |
| `POST tickets/<id>/retry` · `/stop` | 与面板等价的票操作 |

错误语义：400=值无效（issues 逐项）/ 账号检查失败 / 固定拒绝 / 非 JSON 或超限体；404=不存在；409=修订号过期；500=其余。

## 5. panel-only actions（工具没有的能力）

dismiss unavailable 决定、重跑 setup、刷新 Source 显示名、把执行器持有的人类跟帖送回 Eval——后两者是刻意设计（防止绕过执行器归属权）；其余面板操作均有等价工具。

## 6. 搜索

头部搜索可按文本、id、飞书消息 id、存储链接（GitHub 评论 URL）找 Trigger；按 `#12`、GitHub URL 找 Thread；按标题或匹配 Thread 找票。限制：飞书链接只有在本进程内被读过一次之后才可搜（链接解析缓存重启即失）。

## 7. 客户端实现要点

- `src/client/` 是 React 面板（web platform 注入 DSH 侧栏），`provider.tsx` 给所有页提供副本/调用/导航/通知/状态轮询/重启；
- 控件是 DSH 控件的**本地复刻**（bundle 不 import DSH 的 UI primitives，避免耦合）；
- `controls.tsx` 不读上下文（可独立测试）；`panels-*.spec.tsx` 用假 API 按路由应答逐页测试；
- 双语文案集中在 `locales.ts`；glossary 面板 (?) 按钮直开双语术语表；
- 主会话 id（`masterId`）与"导航到会话"集成：面板可从票页跳进 DSH 会话（`navigation.ts`）。
