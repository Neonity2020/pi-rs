# 12 关键设计决策与评估

> 综合：论文解读（MindStudio、Pragmatic AI、MarkTechPost 等）、官方文档中的显式取舍、源码观察。
> 本篇用 ADR 体例浓缩"为什么是这样"，并汇总实验数据、已知局限与开放问题。

## 1. 架构决策记录（ADR）

### ADR-01 Router/Worker 双层，Router 不写代码

- **背景**：单会话跑所有任务 ⇒ 上下文连贯但串行慢、细节互相污染；每事件新会话 ⇒ 吞吐高但缺全局上下文（论文的核心两难）。
- **决策**：一个长命主会话（Router）面对人类并派工；执行拆给一次性 worker 会话（每票一个、上下文隔离）。Router **不分解任务、不写代码**，只 assign + track；刻意限制其工具（无文件写/无子代理，"没有 shell 也能运转"）。
- **理由**：路由与追踪是简单工作 ⇒ 用**轻量便宜模型**；代码生成用最强模型——**模型放置与直觉相反**（便宜的管协调，贵的管干活）。架构天然适配廉价缓存读 token（见 §2 成本）。
- **与 lead-agent 模式的区别**：Router 不做任务分解；分解由 worker 在各自票内完成。

### ADR-02 委托必须是结构属性，不是提示词

- **背景**：论文实验——中性提示"需要时用 sub-agent"5 轮 0 次委托；强提示 4/5。
- **决策**：worker 有独立会话、被移除的通信工具（不能对人提问/展示）、强制边界（report 结构、handback 机制）；Router 的越界通道在代码层封死。
- **后果**：即便换模型、改提示词，分工也不会退化成"单打独斗"。

### ADR-03 领域核心无 I/O、全事务化、单一写入者

- **决策**：`src/core` 除 sha256 外零依赖零 I/O；Engine 每命令一个事务；每类状态唯一写入者；端口（Policy/Assessor/Executor/Outbox/SourceScope/Repositories）在事务内只入队、提交后执行。
- **理由**：多触发源（轮询、事件、工具、HTTP、面板）并发进入时，正确性由结构保证而非靠纪律；测试可用内存仓储双轨验证。

### ADR-04 一切可重放处幂等（内容寻址）

- **决策**：id = sha256(语义内容)；Trigger 确定性 id + 去重；Outbox 回执；GitHub 隐藏评论标记；AgentDelivery 按 requestId 至多一次；Effects generation 计数器；游标"全部入库后才推进"。
- **理由**：轮询源天然可能重放（游标回退、重启、编辑重读）；幂等使"重放安全"成为系统性质而非操作小心。

### ADR-05 Mandate 不可变 + 恢复前重验

- **决策**：accept 铸造不可变授权凭据（强度/策略版本/依据/发送者/scope）；只有 accept、人的 stop、revalidation 失败能改变它；已结束票恢复前按**当前** Policy 重验。
- **理由**：把"当时为什么可以干"固化下来，使策略演进（收紧名单、禁用规则）能**可预期地**作用于存量工作（通过 policy-changed 输入而非粗暴取消），同时杜绝"借旧授权干新事"。

### ADR-06 订阅承载上下文延续，Correlation 只加背景

- **决策**：订阅 Thread 的消息**不检查发送者**地扇出（后续讨论无需再 @）；但扇出不授予任何权限、不产生 Decision；人的自有-Thread 跟帖归属该票 worker（主会话只能 stop）；交还机制让人消息回到 Eval 路径。
- **理由**：把"工作继续"与"新工作授权"两个正交问题分开建模（拒绝表：不对订阅做准入检查、不设"追加到票"决定）。

### ADR-07 观察模式是主动工作的默认起点

- **决策**：accept 三模式 off/observe/auto，默认 observe——推断候选照常研判但只记 `would accept`，不执行。
- **理由**：无人请求的自主行动是最危险的自由度；论文内部部署同样以 would-have-done 日志先行。运营者责任（start narrow）由此有了机制抓手。

### ADR-08 票状态领域自有，派工独立演进

- **决策**：票的 open/ended 与派生 stage 由领域定义；Assignment 独立 pending→running→ended；执行会话崩溃/重启/重试只影响 Assignment。
- **理由**：票可被交接、恢复、多次派工（拒绝表：票状态不跟随 DSH Session）；这让"人直接进 worker 会话干活"等灰区行为也有明确语义。

### ADR-09 上下文即缓存：inline/spill + 读指针

- **决策**：投递给模型的消息带截断正文（任务 1500 / 触发 600 字符）+ `read:` 指针；全文经 `orchestrator_read` 资源按需分页（默认 4000 UTF-16/页）；LRU TextCache；研判用有界窗口（头 5 条 + 两侧各 5 条）。
- **理由**：论文借鉴操作系统 Page Cache 的 Inline/Spill：常用上下文留内存（inline），冷数据落盘按需读（spill），把 token 成本与上下文污染同时压下来；这也让"上下文连续性"不必依赖单一大窗口。

### ADR-10 引擎永不阻塞，副作用先存储后执行

- **决策**：Effects 持久队列 + Passes 2 秒心跳 + `Later` 暂缓；`noWait` 守卫禁止主会话等待（sleep/>30s shell/>5s job）。
- **理由**：等待是注意力杀手：Router 等待会延迟新候选；worker 等待会延迟人的消息。一切"稍后做"都表达为可重试的队列行，崩溃后自动续。

### ADR-11 面板只显示需要人的东西

- **决策**：三问优先级、计数=列表长度、健康不占空间、领域术语、panel-only 操作清单明确列出。
- **理由**：面板本身消耗注意力；它是哲学的直接投影，也是"监督成本"的最后防线。

### ADR-12 等待属于 Source，Eval 从不等待

- **决策**：定时条件（如"4 小时无人认领"）实现为普通 Source；Eval 批内即决，超时重排/`unavailable`。
- **理由**：避免反向依赖与"等待中"状态机的复杂度（拒绝表）；Source 的读位置机制天然适配"等待后重看"。

### ADR-13 账号包装器是默认收敛，不是沙箱

- **决策**：垫片/gitconfig/blockedCommands 收敛默认凭据；`danger-full-access` 不掩盖真实权限；官方直接建议专用 OS 账号。
- **理由**：伪装成沙箱比明确说"不是沙箱"更危险；把隔离责任放到部署层（诚实汇报原则的体现）。

## 2. 实验评估与经济学（转引自论文解读，非本仓库基准）

| 维度 | 结果 | 含义 |
| --- | --- | --- |
| 完成时间 | super-agent 平均 12.4 min / 最差 15.7 min；单会话基线最差 29.5 min | 并行 worker 消除了"会话串行"的尾延迟 |
| Router 扩展性 | 1→40 决策/分钟，单决策 6.4s→1.6s | 批处理使 Router 越忙越划算；Router 便宜模型可持续 |
| Token 成本 | 23.2M 缓存读/轮 ≈ $7（淡季）；无 pass-through 优化 31.8M | 上下文缓存命中是经济模型的核心；pass-through（订阅消息直达 worker，不过 Router 转发）省 25% |
| 委托实验 | 中性提示 0/5；强提示 4/5 | ⇒ ADR-02 |

## 3. 已知局限与开放问题（官方明示 + 文章讨论）

1. **长期记忆退化**：数月运行中保持历史可取用而不撑爆上下文，尚未解决（论文自认）；原型只有 inline/spill + 有限资源读，无总结/遗忘机制；
2. **无界存储**：trigger/disposition/decision/票/回执/版本历史只增不减（[06](06-可靠性与数据完整性.md) §8）；
3. **信任字段未定**：哪些 Trigger 字段可信（actor、Thread 归属）哪些不可信（正文、引用），官方列为开放问题；
4. **部署隔离**：agent profile 固定到独立 DSH 安装，避免宿主升级牵连——列为开放问题；
5. **单仓库范围**：原型是"一个仓库一个 agent"；跨仓库/跨项目协调是论文"更多自主"的下一步方向；
6. **研究代码声明**：可能含 bug、风格不一；发布版与论文/内部版有差异；
7. **评估局限**：实验用耗时工具模拟编码，度量调度而非代码质量；成本按 DeepSeek 淡季定价计算，换高价模型经济性急剧变化。

## 4. 对二次实现者的启示（按重要度排序）

1. **先建模"注意力"再建模"任务"**：消息何时该发、发给谁、多长，比任务分配算法更影响系统成败；
2. **授权凭据化 + 重验**是长命多智能体系统的基石；
3. **幂等先于功能**：轮询型事件源 + 可恢复执行 ⇒ 没有全链路幂等一切都会偶尔错一遍；
4. **把等待挤出去**：任何阻塞模型的 step 都在消耗吞吐与注意力；
5. **文档-代码-测试三角互锁**（docs.spec / model-surface.spec / class-docs.spec）值得原样照抄——它让架构文档本身成为可测试资产。
