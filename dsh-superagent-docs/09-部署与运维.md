# 09 部署与运维

> 来源：官方 `docs/006-deployment.md`、`SETUP.md`、`scripts/dsh-superagent`、`examples/profile.cordis.patch.yml`。
> 部署被设计为**由 coding agent 陪同人类完成**：把仓库给 agent，说"Read SETUP.md and set up dsh-superagent with me"——agent 一次问一个短问题（每条 ≤300 词、带推荐答案）、汇总计划、人确认后执行；密钥永远不进聊天（操作者亲手步骤单列）。

## 1. 运行拓扑

| 组件 | 说明 |
| --- | --- |
| **专用 DSH profile**（`superagent`） | 从 Web 模板创建，独立于日常 profile（插件改进程级 PATH 与 git 配置，需要独立重启/升级）；加载 bundle；面板服务在 `127.0.0.1:3082` |
| **agent GitHub 账号** | agent 以此账号评论/推分支/开 PR；必须用**个人用户账号**（GitHub App 不行——系统读账号的通知流）；其 `gh` 只登此账号（wrapper：`GH_CONFIG_DIR=$HOME/.config/gh-agent`） |
| **飞书 bot（可选）** | 自建应用+bot 能力；`lark-cli` 配置目录独立且 strict-mode bot（**宿主拒绝能扮演真人用户的 CLI**——worker 不得以人身份行事）；wrapper：`LARKSUITE_CLI_CONFIG_DIR=...` |
| **stateDir** | 数据库、锁、`worker-bin` 命令垫片、worker git 配置、默认的票工作目录根 `work/`；升级前必须备份 |
| **巡检** | 在**日常 profile** 里建小时级定时任务（服务挂了它才叫人），prompt 见官方 006——exit 0 静默；exit 2 报告部件错误不重启；exit 3 报告 setup 等待；`manually_stopped` 则不动；exit 1 用 `--respect-stop restart` 恢复，仍失败则读日志自行排障并汇报 |

## 2. 权限与隔离（先读）

- 两个预设都以 `danger-full-access` 以**运营者 OS 用户**运行；命令垫片只改**默认**（agent 凭据优先），不构成隔离——worker 仍可绝对路径执行程序、读运营者 home；
- **正式隔离建议：专用 OS 账号**，其中只放 agent 的凭据；先拿练习仓库练手、只给必需凭据；
- Setup 写入的进程环境收敛：`worker-bin` 垫片排在 PATH 最前（`gh`→agent CLI、`lark-cli`→bot CLI、被禁命令调用即失败；垫片运行目标前把自己的目录从 PATH 移除）；`worker-gitconfig` **替换**全局/系统 git 配置（凭据 helper 指向 agent CLI、SSH 地址重写为 HTTPS、LFS filter；无提交身份、git 永不提示凭据、`GH_TOKEN`/`GITHUB_TOKEN` 被移除）；
- Setup 移除名字含 KEY/PASSWORD/SECRET/TOKEN 的环境变量；`worker-bin`/`worker-gitconfig` 里出现非系统写入的文件 ⇒ setup 拒绝；票目录所在仓库自带凭据配置 ⇒ 票失败。

## 3. 安装

```sh
npm install -g @deepseek-ai/dsh@0.2.1-rc.3          # 公开固定版本；其余须满足 engines.dsh
git clone <repo> dsh-superagent && cd dsh-superagent
pnpm install && pnpm build
dsh superagent --from-default-profile web --dump-config > /dev/null   # 仅新装：会覆盖已有 profile！
dsh plugin --profile superagent add "link:$PWD"
cp examples/profile.cordis.patch.yml ~/.dsh/profiles/superagent/cordis.patch.yml  # 填占位符；飞书需启用对应插件项
```

前置：Node 22.19+/24、pnpm、git 2.32+、Python 3.8+、tmux、`gh` 2.48+（飞书：`lark-cli` 1.0.90 实测）；DSH 已配置模型提供方。机器配置键：`stateDir`（必填）、`promptMaxChars`、`admissionContextMaxPages`、`admissionContextTimeoutMs`；其余限制后面板改，即时生效。

## 4. 启停与状态

```sh
scripts/dsh-superagent start | stop | restart | status
```

- `start`：tmux 会话 `dsh-superagent` 里跑 `dsh --profile superagent`；等待 ≤1 分钟就绪或报 setup 需求；flock 防重复实例；
- `stop/restart`：优雅关停，最多等 5 分钟 worker；**从不强杀**、不碰其他 tmux 会话；
- `status` 退出码：**0** 正常；**1** 没跑/双跑/不应答/runtime 报错（重启可修）；**2** 运行中但某部件（Source/Policy 同步等）报错（重启修不了，人来看）；**3** 等待 setup；
- 日志与控制文件在 profile 的 `.artifacts/`（保留 20 份日志）；
- `--profile/--url/--respect-stop` 可覆盖；仅 `stop` 写停止标记，`start` 清除。

## 5. 首次配置顺序（经管理 API 或面板）

1. **Sources**：GitHub 仓库 `owner/name` + agent CLI 包装路径；飞书 bot CLI、群（mentions/all）、私聊开关。注意：**编辑 Issue 正文加 @ 不算事件**——要发新评论；
2. **Policy**：允许名单（空名单 ⇒ 无请求能成票；飞书可从指定群同步）；两条示例规则可改可删；
3. **Execution**：目录根 + prepare 命令。官方推荐模板（每票一个 worktree 检出）：

   ```sh
   git -C /home/me/src/widgets fetch --no-tags "https://github.com/$DSH_SUPERAGENT_GITHUB_REPOSITORY.git" "${DSH_SUPERAGENT_GITHUB_PR_HEAD:-HEAD}:refs/dsh-superagent/$DSH_SUPERAGENT_TICKET" &&
   git -C /home/me/src/widgets worktree add -b "agent/$DSH_SUPERAGENT_NAME" "$DSH_SUPERAGENT_DIR" "refs/dsh-superagent/$DSH_SUPERAGENT_TICKET"
   ```

   并把**个人 CLI**（登着自己账号的）列入 blockedCommands；
4. **Prompts**：团队三节（GitHub 声明行、审查 bot、提交作者、auto-merge 条件）。

保存返回 `restarting: true` ⇒ 等 `status` 退出码离开 1 再继续，重新读修订号。

## 6. 验收

从允许名单账号在仓库里评论 `@<agent> <request>`；约一个轮询周期内 Overview 出现票；agent 确认、工作、在原对话交付。三条运营者规矩随之交接：**从窄开始、为减噪调优、为它说的话负责**（哲学三条，见 [01](01-设计哲学.md)）。

## 7. 升级

1. 等没有 worker 在回合中；2. 备份 `orchestrator.sqlite`；3. `git pull && pnpm install && pnpm build`；4. `restart` 并检查 status。运行中 Assignment 以恢复便签重启；团队文本与覆盖保留，未覆盖部分跟随新默认；复查"默认内容已更新"部分。**新版迁移过的库旧版打不开**——回滚靠升级前备份。升级 DSH 本体后要重启实例（面板工件匹配）。

## 8. 故障排查速查（精选）

| 症状 | 原因/修法 |
| --- | --- |
| `@… cannot push to …` | 给 agent 账号仓库写权限 |
| `The agent GitHub CLI cannot read its account` | wrapper 里 `auth login` |
| 票失败 `The prepare command failed` | 输出已写明原因（如 clone 路径错）；修命令后 retry |
| `git does not read the github.com credential configuration` | git ≥ 2.32 |
| `The bot lark-cli allows user identities` | 换 bot-only 配置（strict-mode） |
| status 退出 2 | 看输出 `errors` 里部件与详情；重启修不了 |
| status 退出 3 | setup 等待；输出 `setup` 说明缺什么 |
| @ 了却没反应 | 发送者不在名单 / Source 未启用 / 处理暂停 / 编辑正文加 @ 不算（发新评论） |
| 面板说不应答 | 重启中或配置问题；DSH 日志写明原因 |

完整表见官方 `docs/006-deployment.md` §Troubleshooting。
