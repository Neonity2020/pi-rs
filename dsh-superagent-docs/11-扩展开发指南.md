# 11 扩展开发指南

> 来源：官方 `docs/008-cookbook.md`（完整可运行的 webhook Source 教程）与 `tests/` 约定。
> 扩展的主入口是**新增 Source**：领域核心（Engine/票/派工）与执行层不需要动——这正是"少概念"哲学的收益。

## 1. 何时扩展什么

| 想做的事 | 扩展点 | 位置 |
| --- | --- | --- |
| 接入新事件源（GitLab、Slack、Jira…） | 新 SourceKind | `src/sources/<name>.ts`（+ 独立插件入口） |
| 新的"定时条件"型事件（如"Issue 无人认领 4 小时"） | **还是 Source**（等待属于 Source，Eval 永不等待——拒绝表） | 同上 |
| 调整主动工作类型 | Policy 规则（团队设置/提示词），不需要写代码 | 面板 Settings→Eval |
| 调整合并/交付策略 | Delivery requirements 团队节（宿主无 merge 逻辑） | 面板 Prompts |
| 需要新工具语义 | 谨慎：改 `src/app/tools/*` 并同步 `tests/tools.spec.ts`、`model-surface.spec.ts` | `src/app/` |

## 2. 新增 Source 的 11 步（cookbook 摘要）

1. **映射事件到领域**（最关键的一步，持久化后难改）：Trigger=一条消息；Thread=`<conversation>:<首消息id>`；actor=Source 原生发送者 id；Channel 地址=回复目的地；接收范围=准入表行；
2. **写 kind 骨架**：稳定 `kind` id；zod `schema`（**默认值必须什么都收不到**）；`fields` 自动生成表单；声明 `health` 条目（只报"需要人行动"的错误——error 会触发巡检告警）；可选 `facts`（setup 推导的事实）；
3. **翻译 Trigger**：`key()` 生成确定性 id（丢掉 agent 自己的消息）；主 Thread 放 `threads[0]`；`addressed` 只在真被 @ 时设置；`meta` 放 Source 私有字段；编辑=新事件须把版本编入 id；
4. **`scope`**：只依赖 `meta` 与配置（revalidation 也调它）；范围外消息交给 `receive` 存为 filtered（别在轮询循环里静默丢）；`observed` 标记是否全收；`row` 对齐准入表行；
5. **`channel`**：`send` 必须幂等（用消息 id 作幂等键）；返回 `sent` 或 `gone`（**仅限永久不可达**），其他错误 throw 让 Outbox 重试；`allowed` 只查地址与配置；
6. **`threadContext`**（可选，研判需要）：`read` 返回统一形状 `{id, from, at, text, bot?, reply_to?, url?, path?, line?}` 的分页消息；`messageId(trigger)` 定位 Trigger 自身；有图片再实现 `images`/`image`；
7. **`policy` 部分**：allowed 名单 schema + 表单 + `explicit` 说明文案 + `rows`（准入行，id 必须与 `scope.row` 一致）+ 可选 bots 与 sync（名单同步，失败退避 1 分钟→1 小时）；
8. **`environment`**：`DSH_SUPERAGENT_<KIND>_*` 前缀变量（非本 Source 的票返回空值；**永不包含凭据**）；
9. **插件入口与轮询循环**：`inject: ['orchestrator']`；先 `ctx.ready`，`ctx.configured()` 为假不读；每轮现读配置（关了就 paused）；游标**在全部 Trigger 入库后**才推进；逐条容错（`validItems`）；失败计数连续 3 次才报 error；signal 贯穿（取消立即退出）；逃逸的异常变成 Source 健康（DSH 会对未处理 rejection 杀进程）；
10. **注册**：tsdown 加 entry、package.json 导出 `./<name>-watch`、`cordis.patch.yml` insert（**默认 disabled**）、007 文档的模块/测试表补两行（`tests/docs.spec.ts` 强制）；
11. **测试**：仿 `tests/sources.spec.ts`——真 Store + 临时目录、HealthBoard、带替身端口的 Engine、`sourceContextOf` 的 ctx；spy `Commands.run` 与 `withSignal`；至少覆盖：翻译（稳定 id/Thread/actor/human/addressed/无自消息）、一轮（存储一次/filtered/游标/名单 @ 判 explicit）、中断轮次保游标、send 的 sent/gone/throw、Thread 上下文分页、插件注册与 setupPending、Policy 部分。

完整可编译示例（虚构的 `hookq` CLI 队列）见官方 `docs/008-cookbook.md`。

## 3. 开发与质量门槛

- `pnpm check` = 类型检查 + 全部测试 + 构建；
- **测试护航文档与模型面**：
  - `tests/docs.spec.ts`：编号文档只能引用更早文档、本地链接全可解析、无冲突标记、007 的模块表/测试表与实际文件**一一对应**；
  - `tests/model-surface.spec.ts`：模型读得到的一切（工具、提示词、技能、输入）在每角色尺寸预算内校验；
  - `tests/class-docs.spec.ts`：每个类必须有 JSDoc；
- 测试基础设施：`tests/fixtures/host.ts`（模拟 DSH 宿主）、`panel-server.ts`/`panel.tsx`（假管理 API）、`git.ts`（隔离 git 环境）；
- 领域逻辑测试用内存 `MemoryRepositories`，与应用层测试用真 SQLite **双轨验证同一规则**。

## 4. 面向贡献者的阅读顺序建议

1. `docs/001` + `docs/007`（概念 → 实现地图）；
2. `src/core/engine.ts` + `ports.ts`（事务边界与端口）；
3. `src/core/intake.ts` → `evals.ts` → `tickets.ts`（数据流三站）；
4. `src/app/runtime.ts` + `passes.ts` + `effects.ts`（编排与队列）；
5. 想接新源再读 `src/sources/github.ts`（最完整的参考实现）与 cookbook。
