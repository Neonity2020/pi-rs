# pi-rs 文档

README 面向使用者，`docs/` 面向维护者（包括人和 agent）。这里的文档解释**为什么这样设计**，代码与测试解释**具体怎么做**。

## 阅读顺序

| 文档 | 回答的问题 | 什么时候读 |
|---|---|---|
| [goals.md](goals.md) | 这个项目要什么、不要什么、凭什么判断 | 提新功能之前 |
| [architecture.md](architecture.md) | 分层、数据流、关键类型、不变量 | 改代码之前 |
| [plan.md](plan.md) | 现在在哪、下一步做什么、什么不做 | 排优先级之前 |
| [development.md](development.md) | 怎么构建、测试、加工具/加 provider | 第一次贡献时 |

只想快速上手：根目录 [README](../README.md) 的「快速开始」即可。

## 文档边界

| 文件 | 定位 | 不写什么 |
|---|---|---|
| `README.md` | 用户手册：安装、命令、行为、成本 | 内部模块细节 |
| `AGENTS.md` | 给 agent 的操作约定：布局、命令、禁忌 | 长篇设计论证 |
| `docs/goals.md` | 产品目标、非目标、原则、成功标准 | 实现步骤 |
| `docs/architecture.md` | 系统结构与不变量 | 路线图 |
| `docs/plan.md` | 里程碑、候选工作、开放问题 | 已完成功能的教程 |
| `docs/development.md` | 工作流与扩展指南 | 产品取舍 |
| `PLAN.md` / `TODO.md` | 单次任务的临时计划（按需创建） | 长期路线图 |

## 维护规则

- **架构不变量变了，必须同一次提交更新 `architecture.md`。** 计划完成、取消或改变优先级，更新 `plan.md`。
- 文档里的命令要实际跑过；不要写“应该可以”。
- 不在多处复制同一结论。需要引用时给链接，不粘贴。
- 新文档先问：它是否让某个现有文档更短、更清楚？如果不是，可能不需要。
- 默认中文；代码标识符、命令与协议字段保持原文。
