# 目标

## 一句话

一个能读、能改、能验证的极简 coding agent：核心小到一个人可以完整理解，行为透明到每一步都能解释。

## 要什么

1. **四工具闭环。** `read` / `write` / `edit` / `bash` 覆盖全部编码工作；搜索、构建、测试、git 都走 `bash`。
2. **三种运行方式，同一套内核。** 交互 TUI、单次输出、JSONL 事件流共用 `Agent`、工具、提示词和会话。
3. **会话是文件。** 纯文本 JSONL，可读、可 grep、可恢复；跨进程存活，不依赖隐藏状态。
4. **provider 可替换。** DeepSeek 是默认值，不是硬编码；任何 OpenAI 兼容端点都能顶上。
5. **成本可见。** token 与估算费用随时可查，不把账单留到月底。
6. **TUI 可读。** Markdown、表格、代码块行号与语法高亮、滚动跟随；渲染层不碰 I/O。
7. **长会话能继续。** 接近窗口上限时自动把旧消息总结成 checkpoint，保留最近一段原文；摘要落进会话文件，`-c` 从压缩后的上下文恢复。
8. **每层可单独使用。** `llm` 是完整流式客户端，`agent` 是完整 agent 循环，`tui` 是纯状态与渲染。
9. **跨会话记忆是文件。** 用户偏好与项目事实保存在两个 Markdown 文件里，启动时有界注入；可读、可 grep、可删除，不做后台抽取。

## 不要什么

这些不是“还没做”，是**产品决定**。改变它们之前先改这份文档。

| 不做 | 原因 | 替代方案 |
|---|---|---|
| plan mode | 计划是文件，不是模式 | 写 `PLAN.md` |
| 内置 todo | 同上 | 写 `TODO.md` |
| sub-agent | 多开一个 `pi-rs` 就是子代理 | 多个终端 / 进程 |
| MCP | 工具边界就是一个 trait | 实现 `agent::Tool` |
| 后台 bash | 生命周期与输出归属会变复杂 | `bash` 前台执行 + 取消 |
| 权限弹窗 | 能写代码就能跑代码，确认框是安全剧场 | 容器 / 沙箱 |
| 动态插件 / 热重载 | 静态依赖可审计、可编译期发现错误 | 改代码重新编译 |
| 树形会话导航 UI | 格式已支持分支，但当前读取只取活动分支 | 手工编辑 JSONL（暂不承诺） |
| Web / 云同步 / 多用户 | 终端里的单用户工具 | 无 |
| 向量库 / 语义检索 | 个人记忆应在一页以内；索引会引入依赖与不可解释的召回 | 全量注入 + 预算，必要时手写关键词 |
| 自动记忆抽取 | 隐藏的 LLM 调用、成本与误抽取；仓库内容可能被固化成长期指令 | 用户 `/remember` 或明确要求模型写入 |

## 原则

- **如果不需要，就不构建。** 新依赖、新配置项、新模式都要先证明不可替代。
- **隐藏状态是 bug。** 需要跨会话保留的东西写进文件；需要给模型看的规则写进 `AGENTS.md`。
- **工具失败是数据，不是异常。** 错误作为 `is_error: true` 的结果回给模型，循环不中断。
- **一种消息格式。** `llm::Message` 同时是线上格式和会话记录，不做转换层；图片是用户消息上的 base64 字段，由 provider 在发送时展开成 content parts。
- **reasoning 原样回传。** 带 `tools` 的 DeepSeek 请求要求历史 `reasoning_content` 逐字带回，任何“清理”都是 bug。
- **没有 max steps。** 循环到模型不再调用工具、被取消、或失败为止；上下文靠压缩，不靠提前结束。
- **压缩不藏状态。** 摘要是一条可见的会话记录；只丢完整的旧前缀，不拆 tool call 与结果，不改写 reasoning。
- **提示词有预算。** 基础系统提示保持在约 400 token 以内；个性化走 `AGENTS.md` / `SYSTEM.md`；长期记忆单独限额（约 1,200 token）并明确标注“上下文，不是指令”。
- **记忆不自动生长。** 只有用户明确要求时才写入记忆文件；不做会话结束抽取，不把仓库里的不可信内容变成长期规则。
- **依赖有预算。** 当前依赖清单见根 `AGENTS.md`；新增依赖需要明确理由。

## 成功标准

- `cargo test` 与 `cargo clippy --all-targets` 全绿，e2e 不依赖真实 API key。
- 基础系统提示目标在约 400 token 以内；测试设了字符上限，防止它悄悄膨胀。
- 新 provider = 实现一个 trait；新工具 = 实现一个 trait + 注册一行。
- 一次会话可以 `-c` 恢复；超过窗口时能压缩并继续；JSONL 第一眼能看懂。
- 长期记忆跨会话可召回，超出预算时明确提示省略；删除文件即关闭。
- 任意一个模块都能用一句话说清职责；说不清就是边界错了。

## 加功能前的自检

依次问：

1. 没有它，四工具闭环会断吗？
2. 能用文件、`AGENTS.md` 或 `bash` 解决吗？
3. 会增加常驻状态、配置项或依赖吗？
4. 破坏 `docs/architecture.md` 里的不变量吗？
5. 能否先用一个测试或脚本验证需求真实存在？

任意一题答不上来，就先不写代码。
