# Agent Loop 核心逻辑与事件机制

`pi-agent` 负责状态编排和工具执行闭环，核心实现位于 `crates/pi-agent/src/agent_loop.rs`。

## 状态机与回合驱动

一次交互由一次或多次「回合 (Turn)」构成，直到模型完成作答或用户主动中止。

```
                    ┌────────────────────────────┐
                    │      开始新回合 (Turn)      │
                    └─────────────┬──────────────┘
                                  │
                                  ▼
                    ┌────────────────────────────┐
                    │  提取 Steering / 队列消息   │
                    └─────────────┬──────────────┘
                                  │
                                  ▼
                    ┌────────────────────────────┐
                    │    调用 Provider Stream     │
                    └─────────────┬──────────────┘
                                  │
                  ┌───────────────┴───────────────┐
                  ▼                               ▼
          模型直接回复文本                    模型发起工具调用 (ToolUse)
                  │                               │
                  ▼                               ▼
          回合结束 (TurnEnd)               执行 AgentTool
                                                  │
                                                  ▼
                                           获得 ToolResult
                                                  │
                                                  ▼
                                           回填历史并开启下一回合
```

## 消息分级队列

1. **Follow-up 队列**：用户在 Agent 执行期间继续键入的追问或后续命令，排队在当前多轮工具交互彻底结束后执行。
2. **Steering 队列**：引导信号（例如用户在模型调用中间插话或纠正偏离），在当前单个工具调用结束后立即插入下一轮模型上下文，优先干预后续行为。

## 事件通知机制 (`AgentEvent`)

Agent Loop 在运行关键节点发出强类型事件：
- `TurnStarted`：新回合开始。
- `MessageStart` / `MessageDelta` / `MessageEnd`：模型流式响应片段。
- `ToolExecutionStarted`：准备调用工具（包含调用 ID、工具名称与反序列化参数）。
- `ToolExecutionFinished`：工具执行完成（包含调用时长、成功内容或报错详情）。
- `TurnFinished`：当前回合结束，携带用量信息 (Tokens / Cost)。
